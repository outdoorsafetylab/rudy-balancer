部署架構

魯地圖的檔案由志工架設的鏡像站免費提供，分流器負責把每一次下載轉到其中一站。本頁說明這套架構怎麼避開故障，以及哪些情況會讓下載失敗、下游可以怎麼退。

兩個入口

  • rudymap.tw 是主要入口，rudy.oslab.tw 是備援入口。路徑相同，例如 https://rudymap.tw/v1/hgtmix.zip 和 https://rudy.oslab.tw/v1/hgtmix.zip。
  • 兩個入口是各自部署的分流器，網域與 DNS 由不同業者負責，所以其中一家的 DNS 出問題時，另一個入口仍查得到。
  • 兩個入口跑的是同一份程式，也在同一個雲端平台上：程式的錯誤或雲端平台的故障，兩個入口會一起受影響 (見下方失效模式)。

鏡像站

  • 鏡像站由志工架設，分散在不同的主機與網路業者。名單與各站權重在 mirrors.yaml，目前狀態在狀態頁。想架站的話見架設鏡像站。
  • 每週發版後，各站分別同步新檔，有先有後。
  • 狀態頁也列出上游「Cloudflare R2 來源」：魯地圖每次發版寫入的那一份，鏡像站從它同步。分流器同樣每 30 分鐘檢查它，但不會把下載轉到它。上游缺檔或落後時，所有鏡像站都會跟著落後。

分流器怎麼挑站

  1. 每 30 分鐘測一次每個站的每個檔。測不到的不挑，所以一站故障，最慢約 30 分鐘後就不會再被分到。有設每月流量額度的站，用完了也先不挑。
  2. 同一個檔，修改時間比其他站舊的 (發版後還在同步) 先不挑，追上後自動恢復，避免同一個用戶端接連下載的地圖與主題一個新版、一個舊版。各檔分別判斷：某個檔的新版若只在這次分不到的站 (那個檔測試失敗，或那站超過流量額度)，這個檔暫時只分得到舊版，搭配的檔卻可能已是新版。要確定搭配，請比對檔案裡的版本。
  3. 網頁裡的程式發出的請求 (帶 Origin) 只分到允許網頁讀取 (CORS) 的站，而且同一個用戶端 (依 IP) 盡量固定在同一站；那一站對這個檔被排除 (測試失敗、還在同步、超過額度)，或用戶端換了網路，就會換站。一站都沒有時回 502。
  4. 其餘的請求依權重隨機挑一站。
  5. 挑好後回 302 轉址，檔案由鏡像站直接送出。

失效模式

什麼壞了 影響 下游可以怎麼做
一個鏡像站 最慢約 30 分鐘後不再被分到；在那之前，分到那一站的下載會失敗。 重新經入口拿一次網址再下載 (會再挑一次站)。
鏡像站發版後還在同步 舊版的站暫時不分，不影響下載。 續傳直接打原本轉到的那一站並帶 If-Range，不要重新經入口，以免接到另一站或另一週的檔。
Cloudflare rudymap.tw 查不到；架在 Cloudflare 後面的鏡像站約 30 分鐘內被排除，其他站照常。 改連 rudy.oslab.tw，路徑不變。
分流器的程式或它所在的雲端平台 兩個入口一起停。鏡像站本身不受影響。 從先前存下的鏡像站清單 (/v1/sites) 挑一站直接下載。
全部鏡像站都沒有某個檔 那個檔下載不到，分流器回錯誤 (5xx)。 保留手上已有的版本，稍後再試。
線上圖磚 tiles.rudymap.tw 沒有備援入口，停的期間線上圖磚看不到。 要給很多人看、需要不中斷的網站或服務，請自架 CDN 或快取，以 tiles.rudymap.tw 為來源，停的期間快取裡已有的圖磚照常顯示；在山上用的應用程式請改用離線地圖。

建議下游的退路順序

  1. rudymap.tw：連不上 (DNS 查不到、連線失敗、逾時或 5xx) 才換下一個。
  2. rudy.oslab.tw：路徑不變，重試一次。
  3. 先前存下的鏡像站清單：平常下載成功時順便從兩個入口之一 (HTTPS) 讀一次 /v1/sites 存起來，把它當成可以直接連的主機清單；兩個入口都連不上時，從中挑一站，用那一站每個檔的完整網址 (Sources[].URL，含各站的路徑前綴) 直接下載，不要只拿主機名稱接檔名。這樣做下載照常，只是那段期間沒有分流，也不會算進使用報告。

轉址到鏡像站之後的失敗不必換入口：兩個入口轉到的是同一批鏡像站。下載與續傳的細節見開發者整合。

架設鏡像站

歡迎架設鏡像站，一起分擔下載。

怎麼加入

  1. 到魯地圖 GitHub 開一個 issue，寫上站台網址、聯絡方式、想同步哪些檔 (只有台灣，或全部地區)，以及流量有沒有限制。
  2. 由魯地圖作者決定是否加入，以及從哪裡同步檔案。
  3. 確定後我們把站台加進分流器的設定 (mirrors.yaml)，通過下面的檢查後開始分到下載。

要放的檔

路徑與分流器上的檔名相同，例如 https://rudymap.tw/v1/hgtmix.zip 對應 https://你的站/hgtmix.zip。大多數檔在根目錄，每日版在 drops/。分流器分流的檔列在 mirrors.yaml 的 files；其他地區的檔名見 taiwan-topo 的 tools/mirror-configs/。站台可以有路徑前綴，例如 https://你的站/rudy/hgtmix.zip。

伺服器要求

  • HTTPS，支援 HEAD 與 Range (回 206)，並回強 ETag。
  • Last-Modified 是來源檔的修改時間。用物件儲存 (S3 等) 時，Last-Modified 會變成上傳時間，請用會寫入 x-amz-meta-mtime 的工具 (例如 rclone) 同步。分流器靠它判斷哪一站還在同步舊版。
  • 允許網頁讀取：HEAD、GET 回 Access-Control-Allow-Origin: *；預檢 (OPTIONS) 回 2xx，允許 Range 與 If-Range，並公開 Content-Length、Content-Range、Accept-Ranges、ETag。網頁經分流器轉址後送出的 Origin 是 null，所以只能用 *。沒開的站照樣分到應用程式的下載，只是分不到網頁的。

nginx 的設定範例 (kcwu 提供)，加在 server { ... } 裡：

add_header Access-Control-Allow-Origin "*" always;
add_header Access-Control-Allow-Methods "GET, HEAD, OPTIONS" always;
add_header Access-Control-Allow-Headers "Range, If-Range, If-None-Match, If-Modified-Since" always;
add_header Access-Control-Expose-Headers "Content-Length, Content-Range, Accept-Ranges, ETag" always;
add_header Access-Control-Max-Age 86400 always;
if ($request_method = OPTIONS) {
    return 204;
}

某個 location 裡有自己的 add_header 時，不會繼承 server 層的這幾行，要在那個 location 裡再寫一次。

分流器怎麼對鏡像站做健康檢查

  • 每 30 分鐘對每個檔發一次 HEAD，5 秒內沒回應或不是 200 就算這個檔測不到，這個檔先不分到你的站。
  • 某個檔的修改時間比其他站舊 (發版後還在同步)，這個檔也先不分到你的站，追上後自動恢復。
  • 各站目前的狀態在狀態頁；全部的檔都測得到是正常，部分測不到是部分故障。

自我檢查

用 mirror_doctor.py 照健康檢查的方式檢查你的站：它從分流器取得要分流的檔案清單，逐一檢查有沒有這個檔、大小與修改時間是否跟上其他站、ETag、Range 與網頁讀取，最後列出每個檔的結果。只需要 python3，不用另外安裝套件。

curl -s https://raw.githubusercontent.com/outdoorsafetylab/rudy-balancer/master/tools/mirror_doctor.py \
  | python3 - https://你的站

站台有路徑前綴就一起寫上，例如 https://你的站/rudy。全部通過時結束碼是 0，可以放進自己的排程。手動檢查單一個檔：

F=https://你的站/hgtmix.zip
curl -sIL "$F"                         # 200，有 Last-Modified、ETag、Accept-Ranges: bytes
curl -sIL -H 'Range: bytes=0-99' "$F"   # 206
curl -sIL -H 'Origin: null' "$F"        # access-control-allow-origin: *
curl -si -X OPTIONS -H 'Origin: null' \
  -H 'Access-Control-Request-Method: GET' \
  -H 'Access-Control-Request-Headers: range' "$F"   # 2xx，allow-headers 含 range
